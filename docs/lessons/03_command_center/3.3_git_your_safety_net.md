### 3.3 Git: Your Safety Net

Here's the deal that makes agent work safe enough to be fearless: **before an agent touches your project, you save a snapshot. If you love what it did, keep it. If not, one command returns everything to the snapshot.** That's Git. Professionals use it for a hundred reasons; you need exactly this one to start, and it takes four commands.

!!! abstract "What you will learn"
    - Explain what Git does in one sentence and why agents make it non-negotiable.
    - Run the core cycle: `init`, `status`, `add`, `commit`.
    - Roll back unwanted changes — the superpower that makes experiments free.
    - Push a project to GitHub as backup and portfolio.

!!! success "Builder principle"
    Commit before the agent works, commit after you approve. Experiments become free, and free experiments are how you learn fast.

## What Git is

> Git is a time machine for a folder: it saves named snapshots of your project, and can return the folder to any snapshot, anytime.

Each snapshot is a **commit** — the full state of your project plus a message saying what changed. The history of commits is your project's story, told in receipts.

## The core cycle

Do this along with the lesson, inside the project from 3.2:

**Turn on tracking (once per project):**

```console
$ cd ~/builds/quick-win
$ git init
Initialized empty Git repository in /Users/jordan/builds/quick-win/.git/
```

**Check what's changed (any time, constantly):**

```console
$ git status
```

`git status` is read-only and the single most-typed Git command on earth. It shows which files are new or modified since the last snapshot.

**Stage and snapshot:**

```console
$ git add .
$ git commit -m "Starting point: README and notes"
```

`git add .` means "include everything changed"; `commit -m` takes the snapshot with a message. That's a save point, permanent and named.

**See the story so far:**

```console
$ git log --oneline
a1b2c3d Starting point: README and notes
```

## The rollback — why you're really here

Simulate an agent making a mess:

```console
$ echo "TERRIBLE IDEA" > README.md
$ cat README.md
TERRIBLE IDEA
```

Now undo it:

```console
$ git restore README.md
$ cat README.md
# Quick Win
```

Back to the last snapshot. Nothing to fear, ever, as long as the snapshot exists — *which is why you take one before the agent starts.* This two-step rhythm is the heartbeat of every lab from Chapter 4 forward:

```
COMMIT  →  let the agent work  →  review  →  COMMIT (or restore)
```

=== "🌱 No-code lane"

    That's genuinely all you need for now. Four commands (`init`, `status`, `add`, `commit`) plus `restore`. Branches, merges, pull requests — real, useful, *later*. Claude Code can even run Git for you once you understand what the snapshots mean — and now you do.

=== "⚙️ Engineer lane"

    You know Git — so here's the agent-era spin: commit granularity becomes your review granularity. Small, frequent commits around agent turns give you diffable checkpoints of *machine* work (`git diff HEAD~1` = "show me exactly what the agent did"). In Chapter 10, worktrees turn this into parallel agent lanes. Start treating your Git history as an audit log of delegation, not just a change log.

## GitHub: the snapshot lives twice

Git protects you from bad changes; GitHub protects you from a dead laptop — and doubles as your public portfolio.

```console
$ git branch -M main
```

Create a repository on [github.com](https://github.com/new) named `quick-win` (no README — you have one), then connect and push:

```console
$ git remote add origin https://github.com/YOURNAME/quick-win.git
$ git push -u origin main
```

Refresh the GitHub page: your project is on the internet, backed up, timestamped. From now on, ending a work session with `git push` is like locking the door on the way out.

## Try it now

The full safety-net drill, unassisted:

1. In `quick-win`, run `git status` — clean?
2. Add a line to `notes/brief.txt`, run `git status` again — see the change tracked?
3. Commit it: `git add . && git commit -m "Add brief line"`
4. Vandalize any file, confirm with `cat`, rescue it with `git restore`, confirm again.
5. Push, and look at your commit history on GitHub — receipts, visible to the world.
