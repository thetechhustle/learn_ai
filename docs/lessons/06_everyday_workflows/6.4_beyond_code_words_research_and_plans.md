### 6.4 Beyond Code: Words, Research, and Plans

Here's the reframe that doubles this course's value: **Claude Code is not a coding tool. It's an agent that works on files — and almost everything is files.** Your newsletter, your research, your business plan, your course notes, your week. This lesson points the entire toolkit — loop, context engineering, sessions, verification — at the non-code majority of your life.

!!! abstract "What you will learn"
    - Run writing projects as repos with drafts, style guides, and diffs.
    - Do deep research with an agent that reads, organizes, and cites.
    - Manage plans and projects as living files an agent maintains with you.

!!! success "Builder principle"
    If it's text and it matters, it deserves a repo, a session, and the loop. "Code" was never the point — *directed work* was.

## Writing: the draft factory

A writing project set up like a build project:

```
newsletter/
├── CLAUDE.md            ← voice rules, audience, format, hard constraints
├── docs/style.md        ← 3 of YOUR best past pieces — the voice examples
├── drafts/
└── published/
```

The CLAUDE.md for writing works exactly like the one for code — conventions, boundaries, and the gold vein: **examples of good**. Three real pieces of your writing in `docs/style.md` outperform any paragraph describing your voice (2.3's example principle, at full power):

```text
Draft this week's issue from my notes below. Voice per docs/style.md —
match its sentence rhythm, not just its vocabulary. 600 words.
Done means: I read it aloud and it sounds like me on a good day,
and every factual claim has a source I gave you or a TODO marker.
[notes pasted]
```

Then the workflow you already own: review the draft as a *diff* against your intent, request changes in plain language, iterate, commit. Version-controlled writing means fearless editing — hack the draft apart; every prior version is one `git log` away.

And notice what verification means here (4.4 translated): claims sourced, voice read *aloud*, the rude test = "what would my sharpest reader push back on?" — ask the agent exactly that before you ship.

## Research: the evidence trail

Research is a gather-heavy loop with the *findings as files*:

```text
Research question: what do the top 5 booking tools for solo
stylists cost, and what do users complain about most?

Method: check each tool's actual pricing page plus recent user
reviews. Build docs/research/booking-tools.md as you go:
one section per tool — pricing (with source link), top 3 complaints
(with quotes), and your one-line take. Flag anything you couldn't
verify directly as UNVERIFIED.
```

The rules that make agent research trustworthy instead of hallucination-with-headers (2.4 applied):

1. **Findings land in a file, not just chat** — reviewable, citable, permanent.
2. **Sources attached to claims** — "with source link" is non-negotiable.
3. **UNVERIFIED flags welcome** — an agent given explicit permission to mark uncertainty *uses it*; one required to sound complete, guesses.
4. **You spot-check two claims** before the research drives any decision. Two. Every time. (Calibration never retires.)

## Plans: the living roadmap

The saddest file format is the plan written once and never consulted. Plans as agent-maintained files fix the "never consulted":

```
side-hustle/
├── PLAN.md          ← goals, milestones, current status
├── docs/log.md      ← you know this one
```

Weekly, fifteen minutes:

```text
Read PLAN.md and docs/log.md. This week: [what actually happened].
Update the plan: mark progress, flag what's slipping, and tell me —
honestly — whether the March milestone is still realistic. Then give
me the three highest-leverage tasks for next week and why.
```

The agent won't spare your feelings about the March milestone the way you spare your own — text has no optimism bias about itself. That "honestly" gets honored with a directness that's occasionally uncomfortable and always useful.

=== "🌱 No-code lane"

    This lesson might quietly be your biggest unlock: the *entire* toolkit — 90 seconds of pre-flight, briefs, sessions, verification, `/wrap` — needs zero code to pay for itself weekly. Newsletter, meal-prep planning, job search tracking, community-event organizing: pick the words-heavy corner of your life that hurts most and give it the repo treatment this week.

=== "⚙️ Engineer lane"

    The non-code applications *at work* are underrated: design docs drafted against your team's past docs as style guide; incident writeups from raw timeline notes; PR descriptions from diffs; interview debriefs. Same repos, same reviews, same standards as code. The engineers becoming "the one who's scary-productive with AI" are running exactly this on their writing load — which for senior folks is half the job.

## Try it now

Pick ONE (finishing one beats sampling three):

1. **Writer's start:** repo + CLAUDE.md + three voice examples → draft one real piece → ship it somewhere real.
2. **Researcher's start:** one question you actually need answered → the sourced-file method → spot-check two claims → make the decision.
3. **Planner's start:** PLAN.md for your side project → run the weekly review prompt → do the three tasks it surfaced.

Journal which you picked and one thing the *file-based* approach caught that winging-it wouldn't have.
