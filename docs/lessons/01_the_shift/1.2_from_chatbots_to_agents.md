### 1.2 From Chatbots to Agents

Most people's mental model of AI is a chat window: you type, it types back, you copy-paste the answer somewhere useful. That model is already outdated. This lesson replaces it with the one that actually matters: the **agent**.

!!! abstract "What you will learn"
    - Define the difference between a chatbot and an agent in one sentence.
    - Describe the agentic loop: gather, act, verify.
    - Explain why the same model can be a toy in one setup and a teammate in another.

!!! success "Builder principle"
    A chatbot gives you answers. An agent gives you outcomes. Learn to buy outcomes.

## The one-sentence difference

> A **chatbot** responds to you. An **agent** works for you.

Same brain underneath — a large language model. The difference is everything wrapped around it: the ability to read files, run commands, use tools, see the results of its own actions, and keep going until the job is done.

## A concrete comparison

Say your goal is: *"I need a landing page for my candle business."*

=== "🌱 With a chatbot"

    1. You ask for landing page copy. It writes some. You copy it into a doc.
    2. You ask for HTML. It writes a wall of code. You have no idea what to do with it.
    3. You paste the code somewhere, something breaks, you paste the error back.
    4. Forty tabs later you have fragments of a website and a headache.

    The chatbot did its job. *You* were the glue, the hands, and the debugger.

=== "⚙️ With an agent"

    1. You describe the business, the vibe, and what "done" means.
    2. The agent creates the files, writes the code, previews the result, notices the mobile layout is broken, fixes it, and tells you how to see it.
    3. You review, request changes in plain language, and approve.
    4. There is a real website in a real folder, under version control, ready to deploy.

    You were the *director*. The agent was the crew.

## The agentic loop

Under the hood, every competent agent runs the same cycle:

```
┌─→  GATHER   — read files, check state, understand the task
│        ↓
│    ACT      — write code, edit files, run commands
│        ↓
└─   VERIFY   — run it, test it, read the errors, check the result
         ↓
     (repeat until done — or until it needs you)
```

This loop is the single most important mental model in the course. Notice what it implies:

- The agent's first move is *reading*, not writing. What it can see determines what it can do — that's why Chapter 5 (context engineering) is the heart of the course.
- The agent checks its own work — but its verification and *your* verification are different steps. Yours is the one that counts.
- The loop runs many times per task. Small loops, compounding. Exactly like a good human worker.

## Same model, different animal

Here's the part almost everyone misses: **the model is only half the story.** The other half is the *harness* — the tools, permissions, memory, and guardrails around it.

The same model that gives mid answers in a chat window can refactor a codebase, build a website, or automate a workflow when it's running inside a proper harness with the right context. When people say "AI can't do X," half the time they're describing a harness problem, not a model problem.

This course teaches you to build the harness: context (Chapter 5), Skills (Chapter 7), tools via MCP (Chapter 8), guardrails via hooks (Chapter 9), and teams of agents (Chapter 10).

## Where Claude Code fits

Claude Code is the implementation this course builds with: Anthropic's agent that lives in the terminal, reads and writes real files, and runs commands through a gather–act–verify loop. The course uses one concrete tool so you can practice deeply. ## Try it now

Take one task from the list you made in Lesson 1.1 and write it two ways:

1. **As a chatbot request** — "Write me a…"
2. **As an agent brief** — what does *done* look like? What files or information would the worker need? How would you check the result?

Feel the difference? The second one is a skill. It has a name — context engineering — and by Chapter 5 you'll be doing it on instinct.
