### 2.2 Tokens, Context Windows, and Memory

If Lesson 2.1 was the engine, this is the fuel gauge. Tokens and context windows sound like trivia until you realize they explain the most frustrating behaviors you'll ever see from an AI — forgetting things mid-conversation, quality dropping in long sessions, costs creeping up. This lesson turns them into planning tools.

!!! abstract "What you will learn"
    - Explain what a token is and roughly convert between tokens and words.
    - Describe the context window as working memory, and predict what happens when it fills.
    - Distinguish the model's three "kinds of memory" — and know which ones you control.

!!! success "Builder principle"
    The context window is a budget. Builders who spend it deliberately get senior-level output; builders who ignore it get amnesia.

## Tokens: the model's syllables

Models don't read words — they read **tokens**, chunks of roughly ¾ of a word each. `understanding` might be two tokens (`understand` + `ing`); common short words are usually one; code and unusual text break into more.

Rules of thumb worth memorizing:

| Text | Tokens (rough) |
| --- | --- |
| One word | ~1.3 tokens |
| One page of prose | ~500 tokens |
| A typical source-code file | 500–2,000 tokens |
| A whole novel | ~120,000 tokens |

Why care? Two reasons: **cost** (API pricing is per token, in and out) and **capacity** — which brings us to the main event.

## The context window: working memory

The **context window** is the total amount of text a model can consider at once: your instructions, everything it has read this session, the whole conversation so far, and the answer it's currently writing. Modern models handle hundreds of thousands of tokens — entire codebases' worth — but the number is always finite.

Picture a whiteboard. Everything relevant must be *on the board* while the model works. When the board fills, something has to come off — older conversation gets summarized or dropped. That's why:

- A chatbot "forgets" what you told it an hour ago — it scrolled off the board.
- Long agent sessions can drift in quality — the board is crowded with stale detail, diluting what matters.
- Claude Code has commands like `/clear` and automatic *compaction* (summarize-and-continue) — deliberate board management, which you'll use from Chapter 4 on.

And a subtler effect that separates pros from beginners: **it's not just about fitting — it's about focus.** A model reasons best about what's prominent and relevant in context. Stuffing the window with everything you have is like briefing a contractor by handing them your entire filing cabinet. Curation beats volume. That principle has a name — context engineering — and it's Chapter 5.

## Three kinds of "memory" — know which you control

People say "the AI remembers/forgets" about three different things. Untangling them dissolves most confusion:

1. **Training knowledge** (baked in) — everything learned during training. Vast, but frozen at a cutoff date and generic: it knows Python, not *your* project. You don't control this; you pick a model.
2. **The context window** (working memory) — everything in the current session. Powerful but temporary: close the session, board's erased. You control this *within* a session.
3. **Persistent memory** (files on disk) — notes an agent reads at session start and updates over time: CLAUDE.md, memory files, your second brain. This is how agents "remember" across sessions — and it's the piece beginners don't know exists. **You control this completely.** Track 2 of this course is essentially the mastery of it.

=== "🌱 No-code lane"

    The takeaway: when your agent starts fresh tomorrow, it remembers *nothing* about today — unless today's decisions were written into files it reads tomorrow. "Write it down for the agent" will become a reflex by Chapter 5.

=== "⚙️ Engineer lane"

    Mechanically: each API turn is stateless — the entire conversation is re-sent every time (prompt caching makes this affordable). "Memory" is always just *text injected into context*, whether from CLAUDE.md, auto-memory, or tool results. Once you see every feature as "what text enters the window, when," the whole agentic stack becomes legible.

## Try it now

1. Open [Claude](https://claude.ai) and paste in a long article, then ask three questions about it. Notice it never "forgets" the article — it's on the whiteboard.
2. Now ask: `Roughly how many tokens was that article, and how much of your context window did it use?`
3. Journal: which of the three memories were you touching? (Answer: the second — and after Chapter 5 you'd know how to promote the important parts to the third.)
